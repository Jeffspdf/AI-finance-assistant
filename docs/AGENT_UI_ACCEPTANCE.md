# 储蓄规划 UI 与冻结补充集验收

开发分支：`agent/finance-planner`。本节记录当时的源码 UI/holdout 验收；后续真实 UI 联调及 `v0.10.0-rc.1` 候选收口见 `AGENT_REAL_UI_RELEASE.md`，旧 `v0.9.1-rc.1` 不变。

## 入口与操作

源码启动后进入 **储蓄规划 → AI 储蓄规划 · A/B/C**。

- 输入目标、整数月期限、已有储蓄；每次更改输入后，必须重新勾选确认。
- 历史模式读取前三个完整日历月的净额快照；假设模式使用确认的收入和预算，不使用历史账单。
- 历史不足时显示“改用输入假设继续”；点击只切换模式，补齐输入并确认后再计算，不自动混用数据。
- 汇总发送默认关闭。独立勾选后才向已配置模型发送确认输入和脱敏汇总，用于规划与解释；不发送明细、商户名、来源 ID 或证据 ID。
- A/B/C 显示期末预计、目标缺口、每月结余和压缩假设；缺分类依据时 B 明确不能计算，不填零。
- “工具轨迹”和“查看 claims 依据”在本地以只读控件展示实际计算、引用、口径、输入和来源 ID。
- 修改输入重算会新建会话。取消、输入变化、模型配置变化或空间切换后，不接受旧任务迟到的结果。撤销授权后不再继续模型调用；正在进行的网络请求按超时结束。
- 所选有效方案可填入原手动表的 **方案 B**，同时保留基线作为原表方案 A；不保存目标、不写预算。原表仍需用户核对并手动保存。
- 负现金流方案保留负结余展示，但禁止填入旧手动计算器，避免旧表的零截断造成显示口径变化；需先调整假设。

加载、取消、缺输入、无数据、未配置/未授权、模型超时、非法 action、claims 失败及规则回退均有独立状态。模型状态读取现有 `model_client`，不另存配置。

## UI 验证

新增实际 Tk 控件检查覆盖默认确认/授权、规则和合成模型路径、显式切换、重算、依据只读、只填表不保存、迟到响应丢弃、撤销授权、模型配置变化、空间切换及失效数据拦截。

`scripts/verify_savings_planner_ui.py` 从真实 `Desktop` 的新按钮进入，走通 A/B/C、依据、原表填入和假设模式，确认合成源库字节不变。
模拟 1920×1080 的工作区及 150% Tk 缩放：规划窗口 1590×948，无横向溢出；底部按钮固定，滚动可达依据及填表按钮。
所有映射窗口均运行于新建且从不激活的 Windows 测试桌面，不切换用户桌面。控件、布局结果见 `evidence/agent-ui/controls-layout.json`。

最终完整回归：**756 passed，0 failed，0 errors，0 skipped**；计数、耗时及被测源码哈希见 `evidence/agent-ui/regression-summary.json`。

这是实际控件和布局 smoke，**不等同于逐像素视觉验收或真实用户试用**。此阶段 UI 模型路径使用合成提供商，真实提供商调用记录在下方服务层补充集中；后来单独完成的真实模型 UI 联调见 `AGENT_REAL_UI_RELEASE.md`，不回填到本阶段分数。非活动桌面的原生控件截图绘制不完整，未把这些截图当作验收证据。

## 冻结补充集（holdout）

`evidence/agent-holdout/cases.json` 在首次运行前固定，保存基线提交、提示词 SHA256、问题、确认输入及预期。运行时先校验提示词 SHA256；不匹配则在读取密钥及联网前拒绝运行。
本轮未修改 `finance/agent_protocol.py`，未根据补充集结果调参或重跑挑选结果。

| 分组 | 结果 | 外部请求 |
|---|---|---:|
| 六个新真实模型用例 | 6/6 通过，claims 通过，0 回退，平均 4.702 秒 | 20 |
| 三个本地门禁 | 3/3 通过；缺目标、模糊但未确认的期限、只有一个月历史 | 0 |

真实用例覆盖目标已达成、负现金流、分币/预算上限、输入假设、预算修改后新会话重算，以及仅餐饮压缩 5% 的历史模式。H4→H5 的预算改变使 A 的期末预计从 3300 变为 4500，不沿用旧结果。
非法 action、超时和撤销授权仍由工程故障注入验证，**不计入真实模型 holdout 分数**。

限制：该补充集由开发者自拟，问题/输入组合未参与本轮提示词调参，但不是独立团队盲测；历史记录仍复用合成账单模板，不是数据源分布外测试。6/6 仅增加少量冻结场景上的任务完成证据，不能推断通用规划准确率、真实账单效果或用户有效性。

复现（需本机保存并启用模型配置；只发送固定合成数据）：

```powershell
python scripts/evaluate_savings_agent.py --live --settings-dir "$env:LOCALAPPDATA\ShiguangLedger" --case-file docs/evidence/agent-holdout/cases.json
```

结果与文件哈希见 `evidence/agent-holdout/results.json`、`summary.json`。协议 smoke 的首轮失败和修复过程仍保留在 `AGENT_EVALUATION.md`，不与本轮结果混算。
