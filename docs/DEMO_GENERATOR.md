# 自定义生成演示账单（v0.8.1）

切换顶部数据空间为“演示空间”，点击页面中的“生成演示账单”。个人空间不显示该入口；写入服务也拒绝以个人账本为目标。

## 可设置内容

| 设置 | 规则 |
|---|---|
| 起始月份 | YYYY-MM，2000–2100年；允许指定过去或未来月份，便于测试 |
| 连续月数 | 1–12，不能跨出2100年 |
| 每月支出笔数 | 1–500，不含另外添加的收入/转账/退款 |
| 单笔支出范围 | 人民币，最多两位小数，整数分随机取值；最小值大于0且不超过最大值，上限100万元 |
| 每月收入 | 0表示不生成，否则每月增加一笔；生活费或工资；上限1000万元 |
| 转账 | 可选，每月一笔500元，不计收支 |
| 退款 | 可选，每月首笔消费的一半，按整数分取值；保留待处理，不自动抵扣消费 |
| 写入方式 | 默认追加；可选择替换所选月份的全部演示交易，操作前显示影响数量并确认 |

“预览数量”不写库。“生成演示账单”在后台生成并整批保存，完成后刷新当前演示页并选中最后生成的月份。“查看生成账单”进入账本；月份筛选可查看其他生成月份。

同一次生成不接受重复点击；每次主动再生成都有独立身份和来源批次，追加时不会被去重掉。金额、商户、日期和分类样例完全在本地合成，不需要API、模型或用户准备CSV。没有新增依赖。

替换采用同一数据库事务：旧记录软删除、相关对账失效、新来源/批次/交易及审计一起成功或一起回滚。其他月份、预算、目标及个人账本不改变。原始必要字段和审计保留，替换不等于物理数据清除。每批可在“导入批次”中查看或软删除。

内置首次启动的100笔样例和独立六行对账示例继续保留。生成器用于自选月份测试；不声明是实际银行账单或真实消费预测。

## 验证

- 全套回归：169项通过（9.49秒）；新增16项生成器/参数化用例，覆盖闰月、跨月、精确金额、收入0、追加身份、非法输入、个人账本拒绝、指定月份替换、预算/目标保留、失败回滚和对账失效。
- `scripts/verify_demo_generator_ui.py`：输入2024-02、两个月、每月4笔支出、收入/转账/退款，预览并生成14笔；重复点击只保存一批；取消替换无改动；完成后选中2024-03并展示7笔；个人入口隐藏且不能调用；本机150%无横向裁切或回调错误。[UI记录](demo_generator_ui_validation.json)，截图位于screenshots/demo_generator。
- `scripts/verify_dpi_ui.py native`：六页默认/最小尺寸及既有九类弹窗/角色通过；新生成窗口由上面的专用脚本验证。未声称干净虚拟机或混合DPI切换认证。
- 打包自检额外执行相同生成服务：两个月14笔、支出9872分；替换其中一月移除7笔、新增8笔，个人空间保持空；并实际构造生成窗口。

`scripts/verify_packaged_demo_generator.py` 已执行实际v0.8.1 EXE：14笔生成、指定月份替换7→8笔、个人空间拒写和生成窗口构造通过。[实际EXE记录](demo_generator_packaged_validation.json)。实际EXE两次加密配置恢复自检也通过；运行本轮验收没有覆盖用户安装目录。

本轮所有数据和测试Key均为合成值，不读取个人账单，不调用付费模型。
