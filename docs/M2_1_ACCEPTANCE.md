既有v4路径不执行`BASE`、`M1A`、旧`ALTER TABLE`或旧触发器DDL。新库与模式0/3等旧库先沿原路径到4，再增加5，整个过程一个事务；非空旧库在任何DDL之前备份。

历史v4 checksum：`3d9f13acb3466e8dd9201768cad876f374292d9d4fbf2d0a79ebfb4f19053a93`。本步v5 checksum：`db4d84a66b90a0fd7cfa95f2af74a34c62290eb911301baff5904f2ba64243cc`。旧库实际已有的非空历史checksum原样保留，不借升级重新计算覆盖。

迁移顺序：未来版本守卫→迁移前`integrity_check`→`BEGIN IMMEDIATE`串行化写入→复核版本→一致备份→有限DDL→写版本5历史→`integrity_check`和`foreign_key_check`→提交。故障回滚DDL、数据及版本，备份失败不执行DDL。

| 版本/只读 | 模式6读写启动均拒绝且字节不变；只读模式4拒绝原地迁移；只读模式5禁止UPDATE。旧模式0/3路径由原有回归覆盖。 |

| 同消费资金腿 | 选钱包或银行都解析同一事件；既有退款即使外键指向另一资金腿，也共享一个上限。 |
| 同退款跨源 | 已确认退款组只选一个代表；微信/银行得到同一事件，已关联后选另一来源拒绝；两个钱包/不同金额/错误角色/缺成员拒绝。 |
| 上下文变化 | 两条退款分别确认后再去重，或消费金额、退款日期/通道、消费组、上下文改变，旧决定要求复核，不自动搬代表、不写状态。 |
| 来源约束 | 早于消费、非人民币、普通收入、转账、原消费类型/状态不明、批次删除、来源缺失、自关联均拒绝。 |
| 只读一致性 | 成功/拒绝后数据库字节和gross不变，审计不变；WAL下另一连接在校验期间提交编辑，本次用同一快照，下次看到新状态。 |

`validate_refund_link`是预览校验，不预留额度、不确认退款。它返回归一化代表、金额、剩余额度、上下文及算法版本。M2-2写服务必须在同一个`BEGIN IMMEDIATE`事务内重验并保存；直接写SQL的测试夹具不构成公开确认接口。
