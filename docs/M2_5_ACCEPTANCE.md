# M2-5：评审修复与本地候选包验收

日期：2026-11-04。基线：M2-4 `dcb53f6`。本包修复评审指出的 P2 和相关边界，完成实际 EXE 与合成迁移演练。**候选版本为 0.9.0，尚未正式发布；历史写文件警告根因未定位，发布关口仍未通过。** 开发分支继续为 `m2/refund-net`，主分支及已安装客户端未覆盖。

## 评审修复

1. P2 采用 A：`refund_work_items()` 只纳入 `repair_pending=True` 的退款组。持久化修复后从阻塞列表退出；组仍保留 needs_review、来源/快照/审计，去重页提供“重新核对”。重新核对先校验当前来源，不能借修复恢复抵扣。桌面真实控件流程增加修复后列表为空的断言，Web 实测退出列表→修改来源→重新核对→候选确认。
2. Web 组动作按 stored_status：candidate 只可确认，confirmed 只可拆分，其余历史决定只可重新核对。实际服务仍重验状态；用户停留期间发生状态变化时显示错误。
3. Web 口径保存、定点修复、撤销捕获普通异常并显示 `st.error`；同样补齐其他退款写操作的异常边界。注入真实审计写入异常，页面不抛 Streamlit 未处理异常，数据库字节保持原样。
4. Tk 取消关联选择前检查非空，避免空参数的 selection_remove；没有改变 B 契约。原有有效关联仍必须先撤销。

## 实际候选 EXE

打包新增 `--self-test-m2` 与 `--self-test-m2-migration`，必须明确指定隔离数据目录，失败写验收错误日志并以非零退出，不弹无人处理的启动异常框。界面自检复用真实 Tk 控件脚本和双适配器夹具；迁移自检由调用者放入冻结的 v0.8.5 模式 4 合成库，不读取个人数据。

打包冒烟共八组，每组独立目录：通用/TLS、M1a、第五至第八轮、M2 界面、M2 迁移。新门禁为每个进程保存 stdout/stderr；非零退出、缺验收标志或出现历史写文件警告都会停止安装包生成。门禁失败保留日志，不把警告当作成功。

本地候选 EXE 八组均通过，包括：

- 原 M1a 120→60→120 元；退款跨源只扣一次，B 按钮、现金/原消费月切换、负净额、CSV、来源编辑、定点修复和重新核对流程。
- 真实 EXE 执行模式 4→5，迁移前备份与原库行/对象一致，原 ID/金额/审计及 v4 checksum 保留；完整性与外键检查通过。
- 模式 5 退款有效快照恢复；模式 4 快照恢复并升级；撤销/恢复的净额 70→100→70 元；注入 DDL 和恢复维护故障后原业务/对象/审计回滚。
- 未来模式 6 拒绝写入、纯只读查询前后字节不变。
- 实际普通 EXE 主窗口在本机系统 DPI 144 下客户区 1800×1200；合成加密 API 配置连续两次重启保留。没有调用真实模型、没有使用用户 Key。
