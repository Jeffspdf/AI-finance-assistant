# 第二轮体验与视觉评审回应

> 历史记录：本页记录0.7.0的实现。DPI回归和旧1024×680/像素字号方案已由0.7.1修复，当前结果以[第三轮回应](ROUND3_RESPONSE.md)为准。

本轮继续改软件与工程文档。外部报告用于核实问题，不直接授权自动连接模型、使用付费 API、删除角色或引入新框架。优先复用既有 Tkinter 和 Pillow，没有新增 UI 第三方依赖。

| 项目 | 调整与边界 |
|---|---|
| R2-01 | 默认窗口按屏幕可用高度收缩，最小1024×680。主页面单滚动，数据表随页滚动、分页200笔；独立弹窗可以有表格滚动。DPI awareness 启用，字体采用像素尺寸避免高DPI时固定宽侧栏裁字；实际125%/150%系统设置未认证。 |
| R2-02/03 | 深青扁平主题、白底下拉、无斜面边框、主次危险按钮、右对齐金额、表头排序、Canvas细条及红色超支状态。排序用稳定行标识，避免按排序位置编辑错误交易。 |
| R2-04 | 纯函数 insights.py：可复算分类环比、1.5倍历史均值异常、基于平均结余的条件目标估算。每条有为什么和证据。不将相关性写成因果，不保证总有三张，无足够数据就隐藏。当前月未结束时明确限制。 |
| R2-05 | 后台解析、确认前不写库，导入后重复/异常/冲突及超支摘要、待确认入口。前200条预览，完整异常可导出CSV。取消是放弃结果，不是强行终止库内部解析；提交事务期间不允许取消。 |
| R2-06 | 复制上月预算，冲突时询问覆盖或仅补齐；历史均值90%建议先展示并确认，不自动应用。 |
| R2-07 | Ctrl+N / 顶部记一笔，复用日期金额导入校验，标记手动来源。 |
| R2-08 | Ctrl/Shift多选批量分类、同商户且同收支类型全空间应用、单次会话撤销最后一批。该类批量不自动学习，防止误记规则。 |
| R2-09 | Ctrl+K命令面板支持页面、商户、分类、金额条件、上月；非任意自然语言全局搜索。 |
| R2-10 | 用户/助手消息列表，按空间隔离，最多20条，仅本次运行保留；每条回复可继续查询，并打开当时的源记录快照。 |
| R2-11 | 有限月份/分类上下文，宽泛“上个月花了多少”先澄清；准确预算命令经明确月份金额确认后写入。没有让模型执行写操作，不支持任意动作或自由规划代理。 |
| R2-12 | 编辑时显式勾选记住商户，同商户同类型精确匹配，仅新导入记录使用，人工记录不覆盖；设置可查看删除。采用用户可控而非隐式自动学习。 |
| R2-13 | 未执行：本机没有 FINANCE_LLM_* 配置，也未发现可调用的本地模型。未索取或提交密钥，不把mock结果冒充live。既有 --live 评测入口保留。 |
| R2-14 | 趋势图坐标、网格、自适应宽度、悬浮金额；分类图可点击追溯。 |
| R2-15/18 | 去掉大字号宣传标题和开发模型名称，保留紧凑校园头像及桌面宠物；空页面提供直接导入或示例入口。没有删除用户要求的角色。 |
| R2-16/17 | 尚未新增订阅识别、任意页面聊天抽屉；没有深色模式。 |

数据和接口默认保持本地/显式同意边界。首次模型未配置也能看到本地洞察，不因“AI默认关闭”的评语而静默发送账单。

验证脚本：`python scripts/verify_round2_ui.py`。使用临时合成账本验证1024×680、排序定位、多选与撤销、快捷记账、会话/澄清、预算写入取消与确认、异步导入取消不入库和确认入库。`tests/test_round2.py` 独立验证洞察金额及证据、无数据隐藏、学习、预算复制和撤销逻辑。

已有演示数据的145元餐饮仍对应6笔记录。报告再次举的“4笔”不是当前固定样例的准确笔数。截图来自合成数据并包含测试中新增的现金和导入记录，不属于真实用户行为。
