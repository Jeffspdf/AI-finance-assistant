# 第七轮报告复核与处理（v0.8.4）

日期：2026-11-03。基线：v0.8.3 / b13bcca。先核对代码、用隔离合成数据复现，再采用有依据的建议。范围为E1–E3及用户反馈的开发自检安全弹窗；E4–E8是后续里程碑，不因报告列出就视为本补丁任务。

## 对报告的独立判断

| 报告判断 | 核对结果与处理 |
|---|---|
| D1–D4已经落实 | 基本准确；现有代码与验收证据支持，不重写已通过的闭环。 |
| “类型/分类不再能冲突” | 表述过宽。0.8.3只约束转账，收入仍能配餐饮、支出仍能配工资；本轮才增加收入/支出互斥。快速记账和模型路径原本已更严格，不能说所有入口都缺少这项约束。 |
| “打开对账窗口也不会偷偷写审计” | 不准确。纯查询不写库，但窗口打开后会显式调度候选扫描，扫描能修复并写候选/审计。0.8.4新增只读刷新；只读Store的窗口不再调度扫描，可写模式仍保留进入时扫描。 |
| repair_pending重新核对可能失败 | 已复现：显示needs_review、存储confirmed，查询字节不变，旧reopen_group拒绝该存储状态。主要出现在运行中外部异常修改/只读分析；正常可写启动和扫描通常已先修复，不是每次打开就失败。 |
| reopen_group开头调用修复即可 | 不直接照做。同一事务内若后续仍因来源不合法抛错，修复也可能回滚。采用独立“修复此组”操作：保存待复核/缓存后，再由用户补证据与重新核对。 |
| 启动修复、备份缺少入口 | 合理的可见性问题，不等于金额算错。保留已有转账冲突启动修复；补历史和快照入口。新的收入/支出错分类不做静默迁移。 |
| 自动保留最近N个备份 | 未采用自动删除。快照可能是唯一回滚来源；列出大小/位置并逐个确认清理。0.8.3没有持久记录备份用途，不能将所有旧快照重命名或宣称为语义备份。 |
| 应进入退款/真实评测等里程碑 | 产品方向建议，不是已实现功能或本轮缺陷。继续明确未完成，合成回归不代表真实P/R。 |

修前合成复现结果：`income_offers_food=True`、收入+餐饮被服务接受；外部构造失效确认后`effective_status=needs_review / stored_status=confirmed / repair_pending=True`，查询前后文件字节相同，而重新核对报“请选择待核对、已拒绝或已拆分的组”。未读取个人数据。

## 实施结果

- **E1**：核心分类集合统一为收入（工资/生活费/其他收入）、支出（餐饮等九类）、转账（仅转账）。七条写入路径统一校验；编辑/快速记账/模型复用同一选项函数，账本批量操作按选中kind限制，混合类型须分开选择。Web原型仍为共用分类列，保存时逐行拒绝冲突并提示规则。旧收入/支出错分类原样保留，之后保存该交易须明确改为合法组合；不改kind/金额，不启动批量规范化。旧不合法学习规则不会应用到新导入，不静默删除这类旧收入/支出规则。
- **E2**：列表标“待修复（已恢复计数）”，详情区分有效状态与存储状态；“修复此组”需确认，只持久修复选中组，不自动列候选/合并、不改原交易；重复修复不增加审计。修复前禁用“重新核对”，修复后先核对仍不合法的来源。只读刷新不扫描；只读窗口禁用修改操作且不安排初始扫描。
- **E3**：设置和启动修复提示均可打开“修复明细与自动备份”。查看最近200条审计历史、当前空间快照数量/总大小、最近200个快照的时间/用途/大小，预览版本/计数/完整路径，打开目录或确认删除单个快照。新语义快照有明确文件名用途标记，重启仍可发现；旧通用快照标“用途未记录”。删除只限当前账本命名的普通快照，拒绝其他空间、当前库、目录重定向和符号链接；无自动清理，不删除审计。

数据库仍为模式4；稳定用户目录、AppId和独立加密API配置不变。原0.8.3转账语义修复仍先备份、只改分类，不改类型或金额。

## 关于用户反馈的Windows安全弹窗

截图是“打开文件－安全警告/未知发布者”，路径指向本地dist测试EXE，不是Python崩溃。Authenticode检查确认未签名；检查时刚重建文件未带Zone.Identifier，所以没有把具体重复原因武断归为下载标记。微软说明文件来源、类型与发布者等会影响附件安全判断：[Attachment Manager](https://support.microsoft.com/en-us/windows/security/information-about-the-attachment-manager-in-microsoft-windows)。

开发构建原来使用Start-Process走Shell多次打开测试EXE，现改为`packaging/smoke_executable.py`直接启动本地构建，隔离数据、每阶段60秒、检查退出码和新生成标记。没有关闭Defender/SmartScreen、改注册表/执行策略、移除来源标记或安装自签名根证书。这是开发验收启动方式调整，公开安装包仍未签名；正式改善发布者识别需要可信代码签名，也不能保证所有系统不再显示信誉提示。
