# ADR 0002：对账读取与维护边界、转账语义和确认门槛

状态：已实施于v0.8.3。日期：2026-11-03。关联：[ADR 0001](0001-monthly-review-incremental-plan.md)、[第六轮处理记录](../ROUND6_RESPONSE.md)。

## 背景

0.8.2的查询投影会持久修复旧无效组，导致读操作改变状态和审计；分类可出现支出/收入配转账分类；无钱包组缺少专门提示；C级仅禁止确认，却没有具体补证据路径。

## 决策

1. 转账分类保留给转账类型，两个条件必须同时成立。核心服务统一校验，UI联动并引导同时编辑。不会通过分类暗改类型或金额，也不在本补丁强加其他全部收入/支出分类的互斥规则。
2. 写模式启动发现旧冲突时先一致备份，保留kind和amount_cents，将分类规范为该类型的通用分类并标待确认，记录旧值/审计、移除不合法商户规则并使相关组失效。再次启动无冲突就不重复备份或修复。
3. 所有查询连接以SQLite `mode=ro`及`query_only=ON`运行。投影只计算有效状态和计数，不发UPDATE。存储确认已失效时，返回有效needs_review、`repair_pending`和原因，恢复独立计数但保留存储原值。显式`repair_invalid_groups`在写模式启动、扫描、编辑/分类/撤销、删除批次及恢复等维护边界持久更新状态/缓存/审计。
4. `Store(path, read_only=True)`不创建目录、迁移或修复，只接受当前受支持模式；写操作由SQLite或显式只读检查拒绝。只读分析与备份检查不需要获得写库权限。
5. 零钱包组保持人工确认能力，但核心接口要求严格布尔`acknowledge_no_wallet=True`；GUI先常规确认，再独立提示可能是两笔真实消费，二次取消不提交。审计记录额外确认。新政策不单独推翻其他证据仍有效的历史确认。最多一个钱包、C级/过期不可确认规则保持。
6. C级诊断为只读函数，具体报告缺失账户/有效绑定、时间差、通道、商户和候选歧义，提供绑定与重扫。缺账户的旧来源引导用户核对、删除对应旧批次并选账户重新导入；不自动回填账户、不伪造证据以升级置信级别。

## 结果与限制

金额口径不变：仅有效确认消费组排重；退款待处理且未扣减。查询能在外部数据异常时给出安全计数，但持久修复需明确维护或下次写模式启动。模式版本保持4；旧二进制无法自动获得新约束，不支持直接降级写库。自动备份含原始数据，与账本同等私有，不进入仓库。

此决策不实现退款净额、支付宝专用格式、批量/三成员UI、真实样本准确率或大规模性能保证。验证方法与实际边界见处理记录。
