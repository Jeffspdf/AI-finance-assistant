# ADR 0003：分类集合、选中组修复与快照可见性

状态：v0.8.4已实施。日期：2026-11-03。补充[ADR 0002](0002-reconciliation-read-write-boundaries.md)，评估过程见[第七轮记录](../ROUND7_RESPONSE.md)。

1. 收入、支出、转账使用互斥的固定分类集合，所有交易写入验证kind/category。现有收入/支出错分类不自动改写；下一次保存时须由用户更正，金额和kind不会因分类自动变化。原转账冲突的备份后启动修复策略保持。商户学习忽略不合规规则，模型与快速输入复用分类选项函数。
2. 查询仍只读，`repair_pending`是有效状态不同于存储状态的信号。独立“修复此组”只处理当前选中的无效确认并提交待复核/缓存/审计，幂等，不自动确认。避免把修复放进可能因来源仍无效而回滚的重新核对事务。用户补证据后再重开/扫描。只读窗口不扫描，新增只读刷新与可写候选扫描区分。
3. 语义修复快照文件名显式标记用途，旧快照用途未记录就保留未知标记。设置提供修复历史、备份路径/大小/版本/计数与手动逐个删除，确认包含无法使用该快照回滚的提示。无自动轮转删除；清理范围只限当前账本的受管普通快照，拒绝跨空间、当前库、目录重定向与符号链接。清理不删除修复审计，不对已发布旧文件伪造用途。
4. 开发自检直接启动本地EXE，保留隔离目录/超时/退出码/新标记要求。无需改变Windows安全设置。发行版代码签名仍未配置，不用自签名根证书假装可信发布者。

模式保持4；这些维护动作不实现退款净额、真实准确率评测或M1b格式扩展。
