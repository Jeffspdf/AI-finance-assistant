# ADR 0005：M2退款净额设计草案

日期：2026-11-04。状态：产品口径已确认，技术方案待确认/实施；运行时仍为v0.8.5、模式4。[完整差距与方案](../M2_GAP_AND_IMPLEMENTATION_PLAN.md)。

1. 用户确认默认cash、预算采用net，同时展示gross。原消费月可切换。月净额可负，单笔累计退款不得超过消费；退款不作收入。
2. 拟增加refund_links和ledger_settings，有限迁移4→5先一致备份，保留模式4历史，DDL/版本/审计原子完成；未来版本拒写，恢复同样重验。
3. refund_duplicate独立于purchase_duplicate，先人工确认跨源退款事件，再由一个代表关联原消费。物理UNIQUE(refund_txn_id)不足以防事件重复，服务层必须按逻辑退款/消费事件验证唯一与上限。
4. transactions()维持gross，新spending_view产生内存负支出调整。源金额与日期不改，全部金额入口复用，证据同时含原消费/退款/组/决定/口径/时间。统计计数不把调整项当新增消费，非正分母不计算支出占比。
5. 源编辑、分类各入口、组变化、批次删除、演示替换和恢复使相关决定失效并保留审计；组代表变更不自动搬运旧资金决定。读取纯重验，维护显式持久化。
6. 原消费显示“已退款”不等于存在独立退款流水。角色不明保持复核，不凭文字克隆退款或自动抵扣。用户确认原消费角色需要独立审计。
7. 真实数据当前未具备，仅准备离线工具与模板。工具声明、合成样本和表格填满均不等于真实验证；人工独立扫描分母、授权来源和最终验收仍由团队负责。

此ADR未改变数据库或宣布M2完成。M1a功能冻结，超范围适配/性能/UI扩展须有实际触发数据再另行记录。
